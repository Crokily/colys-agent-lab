# Idea vocabulary and derivation

The idea must come from the user's own material. This file gives families to search in, so candidates differ from run to run, and a worksheet to derive them.

## Families

Each family names a kind of "one idea", gives examples seen in the reference library, when it fits, and its usual failure.

| Family | Examples | Fits when | Usual failure |
| --- | --- | --- | --- |
| **One object** | Chrome storage blobs (Code Storage); an airplane window; a product frame holding artwork (Dia) | The person or product has a real thing that can be shown: a device, a tool, a document, a place | Object is decorative and does nothing across the page |
| **One material** | Paper with hairlines; ink on newsprint; frosted glass; film grain | The voice is editorial, technical or archival | Material applied to everything equally, so nothing has hierarchy |
| **One typographic move** | Giant name or noun crossing an image edge (Exo Ape); a masthead; numbers set as figures with mono captions | The story is in words and proof, and the imagery is secondary | Big type with nothing under it; the "giant name alone" hero |
| **One motion** | Section takeover; a nav that expands into work previews (Polaroid); drag with constraints and return; morphing frames | There is a clear sequence to tell, or a lot of work to preview | Motion for its own sake; scroll hijacking; no reduced-motion path |
| **One world** | A 3D room after a start screen (Yoshik); a desktop; a map | The person's identity is a place or a play space, and visitors will accept an entry step | Entry cost too high; content hard to reach; retro-OS cliché |
| **One document form** | README-like page (Code Storage); a newspaper front page; a letter; a receipt; a changelog | The work is written or versioned, or the person is a builder of tools | Parody instead of form; fake issue numbers and fake mastheads |
| **One scenery state** | A sky that moves from morning to night; a tide; a season; light through a window | The user wants colour and atmosphere and there is a reason for the change | Scenery as wallpaper with text pasted on it; identical head and tail |
| **One instrument** | A waveform that responds to real audio; a terminal that runs; a chat that answers | The work itself can run in the page | Faked "live" data presented as real |

Mix at most two families. One carries, the other supports.

## Derivation worksheet

Fill this in from phase 1 material, in writing, before proposing anything.

1. **Real things.** List every concrete noun in the user's world: tools they built, surfaces their work lives in (a terminal, a chat app, a spreadsheet, a stage), places, habits, materials they touch, sounds they make.
2. **Proof.** List the three to five facts that carry weight, verified.
3. **Voice.** One sentence with a point of view that the proof supports.
4. **Candidates.** For at least three families, write one candidate: object or move, where it comes from in step 1, what it does on the first screen, how it changes by the end, cost to build well.
5. **Score.** For each candidate: fit to material (does it come from step 1?), distinctness (would a different user have arrived here?), feasibility at high quality with the available stack, and how it handles many items without a long scroll.
6. **Choose and state.** One sentence: "The site is a ___ that ___." Name one object or move.

## Anti-convergence check

Before presenting candidates, answer these:

- If I swapped this user for someone with different work, would the idea still apply? If yes, discard it.
- Does the idea reuse the outcome of the worked example (window, generated sky, name crossing a frame, proof band)? If yes, change the object, the material or the move until it is this user's.
- Is the idea just a collection site trend (equal cards, glass panels, purple gradients, giant name hero, retro desktop)? If yes, it is not an idea.
- Can the user's three strongest works each be *shown doing their thing* inside the idea? If not, the idea is too thin to carry the site.

## Presenting candidates

Use words plus ASCII sketches of the first screen for each candidate. State a recommendation and its reason. Let the user redirect; their reaction is design input, not a vote to be won.
